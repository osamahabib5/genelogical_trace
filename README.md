# Genealogy Ancestry Chatbot

An AI-powered chatbot application for tracing African American genealogical ancestry through historical documents and records.

> **Runtime architecture (venv + Supabase):** the application no longer runs on Docker.
> - **Backend:** FastAPI + Uvicorn running inside a Python **virtual environment (`venv`)**
> - **Database:** **Supabase** (managed PostgreSQL with `pgvector`) instead of a local Postgres container
> - **LLM:** **DeepSeek API (primary)** or **Groq API (secondary)**
> - **Frontend:** React dev server via `npm start`

## Features

🔍 **Document Processing**
- Upload and process PDF, DOCX, TXT, and JSON documents
- Automatic text extraction and chunking
- Footnote extraction and linking for DOCX documents
- Support for journals and application templates

💾 **Vector Database Storage**
- Supabase PostgreSQL with the pgvector extension for semantic search
- Stores document chunks and extracted genealogical data
- Efficient similarity-based retrieval

🤖 **AI-Powered Chatbot**
- Semantic search across uploaded documents
- Natural language queries about ancestry information
- Context-aware responses with source citations
- Genealogical entity extraction (names, dates, locations, occupations, relationships)
- Responses generated by the **DeepSeek** API (primary) or **Groq** API (secondary)

👨‍👩‍👧‍👦 **Family Tree Search**
- Search for specific people in records
- Find connected family members and relationships
- View complete genealogical connections

📊 **Web Interface**
- Modern React-based UI
- Document upload and management
- Chat interface with sources
- Family tree visualization

## Prerequisites

- Python 3.10+

## Setup Instructions

### 1. Clone and Create the Virtual Environment

```bash
git clone <your-repository-url>
cd genealogy_traceline

# Create the virtual environment
python -m venv venv

# Activate it
venv/Scripts/activate        # Windows
source venv/bin/activate     # macOS / Linux

# Install backend dependencies
pip install -r app/backend/requirements.txt
```

### 2. Configure Environment Variables

```bash
cp .env.example .env         # macOS / Linux
copy .env.example .env       # Windows
```

Edit `.env`:

```env
# ---- Supabase PostgreSQL connection ----
# Copy this from: Supabase Dashboard → Project Settings → Database → Connection string
DATABASE_URL=postgresql://postgres.<PROJECT_REF>:<DB_PASSWORD>@aws-0-<REGION>.pooler.supabase.com:5432/postgres

# ---- LLM provider: deepseek (primary) or groq (secondary) ----
LLM_PROVIDER=deepseek

# DeepSeek (primary)
DEEPSEEK_API_KEY=sk-your-deepseek-api-key
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_BASE_URL=https://api.deepseek.com

# Groq (secondary / fallback)
GROQ_API_KEY=your-groq-api-key
GROQ_MODEL=llama-3.1-8b-instant

# ---- Embeddings (DeepSeek and Groq are chat-only APIs) ----
# Local Ollama is the default; OpenAI is optional for 1536-dim embeddings.
EMBEDDING_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_EMBED_MODEL=nomic-embed-text
# OPENAI_API_KEY=your-openai-api-key
# OPENAI_EMBEDDING_MODEL=text-embedding-3-small

# Frontend
REACT_APP_API_URL=http://localhost:8000
```

### 3. Set Up the Supabase Database

1. Create a project at [supabase.com](https://supabase.com/).
2. Enable the pgvector extension: **Dashboard → Database → Extensions → search "vector" → Enable**.
3. Copy your connection string: **Dashboard → Project Settings → Database → Connection string → Session pooler** (port `5432`) or **Direct connection**. Paste it into `.env` as `DATABASE_URL`.
4. Open **Dashboard → SQL Editor → New query**, paste the contents of `database/supabase_setup.sql`, and run it.

The script creates the `vector` extension, all application tables, indexes, and a helper view.

### 4. Start the Backend

```bash
cd app/backend
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

The backend verifies/creates tables on startup and runs at `http://localhost:8000` (interactive docs at `/docs`).

### 5. Start the Frontend

```bash
cd app/frontend
npm install
npm start
```

Open your browser and navigate to: **http://localhost:3000**

## LLM Provider Configuration

### DeepSeek (primary)

Set `LLM_PROVIDER=deepseek` in `.env`. DeepSeek exposes an OpenAI-compatible API:

```python
# pip3 install openai
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ.get('DEEPSEEK_API_KEY'),
    base_url="https://api.deepseek.com",
)

response = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[
        {"role": "system", "content": "You are a helpful assistant"},
        {"role": "user", "content": "Hello"},
    ],
    stream=False,
    reasoning_effort="high",
    extra_body={"thinking": {"type": "enabled"}},
)

print(response.choices[0].message.content)
```

### Groq (secondary)

To switch to Groq, change `.env`:

```env
LLM_PROVIDER=groq
GROQ_API_KEY=your-groq-api-key
GROQ_MODEL=llama-3.1-8b-instant
```

### Embeddings

DeepSeek and Groq do not offer embedding endpoints, so document embeddings come from a separate provider:

- **Local Ollama** `nomic-embed-text` — 768 dimensions (default)
- **OpenAI** `text-embedding-3-small` — 1536 dimensions

The dimension must match the `vector(...)` column type in the Supabase schema (see `database/supabase_setup.sql`).

## Supabase Database Setup

### Connection String

Format:

```
postgresql://postgres.<PROJECT_REF>:<DB_PASSWORD>@<DB_HOST>:<PORT>/postgres
```

| Mode | Host | Port | Notes |
| ---- | ---- | ---- | ----- |
| Session pooler | `aws-0-<REGION>.pooler.supabase.com` | `5432` | Recommended for the backend |
| Transaction pooler | `aws-0-<REGION>.pooler.supabase.com` | `6543` | For serverless/short-lived clients |
| Direct connection | `db.<PROJECT_REF>.supabase.co` | `5432` | IPv4-only; fine for local dev |

### Database Script

`database/supabase_setup.sql` (run once in the Supabase SQL Editor) creates:

- The `vector` extension (pgvector)
- Tables: `documents`, `document_chunks`, `ancestry_data`, `document_footnotes`, `query_history`
- B-tree indexes for lookups and IVFFlat indexes for vector similarity search
- A `recent_ancestry_queries` helper view

Notes:

- The app connects with the `postgres` role via the connection string, so Supabase Row Level Security (RLS) does not apply to these queries.
- Keep the pgvector dimension consistent: `vector(768)` for Ollama `nomic-embed-text` (default) or `vector(1536)` for OpenAI. Change the script and `config.py` together.
- `SERIAL` primary keys are used so integer IDs line up with the SQLAlchemy models in `database.py`.

## API Endpoints

### Documents

- **POST** `/api/documents/upload` - Upload a document
  ```bash
  curl -F "file=@document.pdf" -F "document_type=journal" http://localhost:8000/api/documents/upload
  ```

- **GET** `/api/documents/list` - List all documents
- **GET** `/api/documents/{document_id}` - Get document details
- **GET** `/api/documents/{document_id}/footnotes` - Get document footnotes
- **DELETE** `/api/documents/{document_id}` - Delete a document

### Queries

- **POST** `/api/queries/search` - Search genealogical information
  ```bash
  curl -X POST -H "Content-Type: application/json" \
    -d '{"query":"Who were the ancestors of John Smith?"}' \
    http://localhost:8000/api/queries/search
  ```

- **POST** `/api/queries/ask` - Chat with the genealogy bot
  ```bash
  curl -X POST -H "Content-Type: application/json" \
    -d '{"query":"Tell me about African American soldiers in the Civil War"}' \
    http://localhost:8000/api/queries/ask
  ```

- **GET** `/api/queries/person/{name}` - Search for a specific person
- **GET** `/api/queries/family/{person_name}` - Search family connections
- **GET** `/api/queries/documents/{doc_type}` - Get documents by type
- **GET** `/api/queries/history` - Get query history

## Data Schema

### Documents Table
- `id`: Document ID
- `title`: Document title
- `document_type`: 'journal' or 'application'
- `file_name`: Stored filename
- `content`: Full text content
- `upload_date`: Timestamp
- `metadata`: JSON metadata

### Document Chunks Table
- `id`: Chunk ID
- `document_id`: Reference to document
- `chunk_text`: Text content (500 chars max)
- `chunk_number`: Sequence number
- `embedding`: Vector embedding (768 dimensions with Ollama; 1536 with OpenAI)

### Ancestry Data Table
- `id`: Record ID
- `document_id`: Reference to document
- `person_name`: Extracted person name
- `birth_date`, `death_date`: Life dates
- `birth_location`, `death_location`: Geographic info
- `occupation`: Job/profession
- `relation_type`: Family relationship
- `related_to`: Related person's name
- `embedding`: Vector embedding

### Document Footnotes Table
- `id`: Footnote ID
- `document_id`: Reference to document
- `chunk_id`: Reference to chunk (if linked)
- `footnote_number`: Footnote number (e.g., "120")
- `footnote_text`: Full footnote content
- `page_number`: Page number (optional)

### Query History Table
- `id`: Query ID
- `query_text`: The text of the user's query
- `results`: JSON results from the query
- `query_date`: Timestamp of the query
- `relevance_score`: Optional relevance score

## Troubleshooting

### Supabase Connection Error
- Verify `DATABASE_URL` in `.env`: correct `<PROJECT_REF>`, `<DB_PASSWORD>`, host, and port.
- Use the **session pooler** (port `5432`) for the backend; port `6543` is the transaction pooler.
- Check that the project is not paused (paused projects can be restored from the Supabase dashboard).
- Confirm the pgvector extension is enabled and that `database/supabase_setup.sql` has been run.

### DeepSeek API Errors
- `401` — check `DEEPSEEK_API_KEY` in `.env`.
- Model not found — verify `DEEPSEEK_MODEL` is a valid model name for your account.
- Rate limits / insufficient balance — check the DeepSeek platform console.

### Groq API Errors
- Verify `GROQ_API_KEY` and `GROQ_MODEL` when `LLM_PROVIDER=groq`.

### Embeddings Not Working
- Confirm the embedding provider key (`OPENAI_API_KEY`) is set in `.env`.
- Make sure the embedding dimension matches the `vector(...)` columns in Supabase.

### Frontend Not Loading
- Run `npm install` inside `app/frontend/`.
- Check that `REACT_APP_API_URL` points to `http://localhost:8000`.
- Verify the backend is running and that CORS origins in `main.py` allow the frontend origin.

### Reset the Database
Use the commented-out `DROP TABLE` statements at the bottom of `database/supabase_setup.sql`, then re-run the script.

## Performance Optimization

### Vector Indexes
`database/supabase_setup.sql` creates pgvector IVFFlat indexes for fast similarity search. For large collections you can switch to HNSW (supported on Supabase):

```sql
CREATE INDEX idx_chunks_embedding ON document_chunks
  USING hnsw (embedding vector_cosine_ops);
CREATE INDEX idx_ancestry_embedding ON ancestry_data
  USING hnsw (embedding vector_cosine_ops);
```

Rebuild indexes if needed:

```sql
REINDEX INDEX idx_chunks_embedding;
REINDEX INDEX idx_ancestry_embedding;
```

### Connection Pooling
- The backend uses SQLAlchemy connection pooling; adjust pool settings in `config.py` for more concurrent requests.
- Connect through the Supabase **session pooler** (port `5432`) so the pooler manages Postgres connections for you.

## Security Notes

- Never commit `.env` — keep API keys and the Supabase password out of version control.
- Use a strong Supabase database password and rotate it regularly.
- Store DeepSeek/Groq/OpenAI keys only in `.env` or a secret manager, never in code.
- Enable HTTPS in production (e.g., behind a reverse proxy).
- Restrict CORS origins in `main.py`.
- Validate all file uploads.
